# CRM Account Signal Contract

## Purpose

This contract defines the future read-only CRM/account signal interface for Marketing segments. It covers Goal 19.1 and Goal 19.2 only: account, opportunity, lifecycle, owner, health, onboarding, renewal, upsell, and winback fields that Marketing may use as segmentation inputs.

No runtime CRM client, database migration for CRM master data, journey runtime behavior, or admin UI behavior is approved by this contract.

## Ownership

The CRM/account service is the source of truth for:

- Account and company master records.
- Opportunity records and sales pipeline stages.
- Account lifecycle stage, owner assignment, health, onboarding status, renewal state, and customer-success notes.
- Account-to-contact relationship references.

Marketing owns only:

- Segment definitions that reference CRM/account fields.
- Dry-run and execution decisions derived from source-owned CRM/account signals.
- Campaign, journey, run, suppression, frequency-cap, and audit evidence.
- Stored source references and decision snapshots needed to explain a campaign decision.

Marketing must not create, update, delete, or become the editable source for accounts, companies, opportunities, owners, notes, lifecycle state, health state, onboarding state, or CRM contact relationships.

## Runtime Contract Generated By Marketing

No deployed CRM/account service exists in the current remote repositories. Marketing therefore defines the consumer contract below and ships a source client that is disabled by default. The client only runs when `CRM_ACCOUNT_SERVICE_URL` is configured by deployment.

Generated runtime facts:

- Base URL: `CRM_ACCOUNT_SERVICE_URL` with no source-code default.
- Auth method: optional bearer token from `CRM_ACCOUNT_SERVICE_TOKEN`; if unset, no authorization header is sent.
- Read endpoint path: `CRM_ACCOUNT_SIGNAL_PATH`, default `/marketing/account-signals`.
- Pagination: cursor pagination with `limit` and `cursor`; Marketing requests `CRM_ACCOUNT_SIGNAL_LIMIT` or `100` and follows up to `CRM_ACCOUNT_SIGNAL_MAX_PAGES` or `1` page by default.
- Rate-limit behavior: HTTP `429` and other source errors fail safely before notification delegation; Marketing does not retry inside campaign execution.
- Timeout: `CRM_ACCOUNT_SIGNAL_TIMEOUT_MS` or `5000` ms.
- Error response contract: JSON errors should use `{ "error": "stable_code", "message": "human-readable summary", "fields": {}, "requestId": "optional" }`; Marketing records sanitized failure evidence and does not expose tokens or raw response bodies.

If the CRM/account source is unconfigured, unreachable, malformed, stale, or returns unsupported schema versions, Marketing fails the CRM source safely and produces no delivery recipients from CRM state.

## Read Endpoint Contract

Generated endpoint:

```text
GET {CRM_ACCOUNT_SERVICE_URL}{CRM_ACCOUNT_SIGNAL_PATH:-/marketing/account-signals}
```

Required query scope sent by Marketing:

- `tenantId`
- `appId`
- `brandId`
- `limit`

Optional query scope sent when present on the campaign, segment, or rules:

- `businessId`
- `environment`
- `accountId`
- `companyId`
- `accountOwnerId`
- `opportunityId`
- `lifecycleStage`
- `opportunityStage`
- `healthStatus`
- `onboardingStatus`
- `renewalDateFrom`
- `renewalDateUntil`
- `sourceUpdatedSince`
- `sourceUpdatedUntil`
- `cursor`

Preferred response wrapper:

```json
{
  "schemaVersion": "marketing.crm_account_signals.v1",
  "items": [],
  "nextCursor": null
}
```

## Field Contract

| Field | Requirement | Owner | Marketing usage |
| --- | --- | --- | --- |
| `accountId` | Required for account signals; required on opportunity signals when linked | CRM/account service | Stable source reference and segment predicate. |
| `companyId` | Required when the source has a company record | CRM/account service | Stable company reference only. |
| `tenantId` | Required | Tenant/app registry and CRM/account source reference | Scope validation and segment filtering. |
| `businessId` | Optional | Tenant/app registry and CRM/account source reference | Scope filtering when present. |
| `appIds` / `appId` | Required when app-scoped | Tenant/app registry and CRM/account source reference | Campaign and segment scope matching. |
| `brandId` | Required when brand policy differs | Tenant/app registry and CRM/account source reference | Sender/policy scope matching. |
| `accountOwnerId` / `ownerId` | Optional | CRM/account service | Owner-based segmentation reference only. |
| `lifecycleStage` | Optional enum | CRM/account service | B2B onboarding, activation, renewal, upsell, winback segmentation. |
| `opportunityStage` | Optional enum | CRM/account service | Pipeline-based segmentation. |
| `opportunityStatus` | Optional enum | CRM/account service | Open/won/lost/stale opportunity segmentation. |
| `healthStatus` | Optional enum | CRM/account service | Account health segmentation. |
| `healthScore` | Optional numeric 0-100 | CRM/account service | Threshold segmentation and dry-run evidence. |
| `onboardingStatus` | Optional enum | CRM/account service | Onboarding journey and campaign segmentation. |
| `renewalDate` / `expectedCloseDate` | Optional ISO date | CRM/account service | Renewal and opportunity-window segmentation. |
| `sourceUpdatedAt` | Required | CRM/account service | Freshness, audit evidence, and safe stale-source handling. |
| `contactRefs` | Optional references only | CRM/account service for relationship; auth/leads for contact truth | Candidate subject references for later recipient resolution. |
| `attributes` | Optional object | CRM/account service | Small, non-secret segmentation attributes only. |

## Contact And Consent Boundary

`contactRefs` are relationship references only. They must not contain email addresses, phone numbers, Telegram handles, WhatsApp identifiers, consent state, unsubscribe state, or preferred-channel truth.

Before any real delivery, Marketing must resolve reachable recipients through auth/leads contracts and enforce source-owned consent, unsubscribe state, frequency caps, throttling, owner approval, idempotency, max-send limits, max-30 chunking, registry validation, and notification delegation.

CRM account lifecycle state must never imply marketing consent.

## Safe Failure And Audit Requirements

When a future CRM source is unreachable, unconfigured, stale, malformed, or returns unsupported schema versions, Marketing must skip or fail safely before notification delegation and record audit evidence such as:

- `crm_account_source_unconfigured`
- `crm_account_source_unavailable:<reason>`
- `crm_account_source_malformed:<reason>`
- `crm_account_no_matching_accounts`
- `crm_account_no_resolvable_contact_refs`

Dry-run output may include account IDs, company IDs, opportunity IDs, lifecycle states, and decision reasons. It must not include raw contact addresses, private customer-success notes, tokens, provider credentials, or message bodies.
